Every repository you own, as one graph.

repo-mcp indexes GitHub, GitLab and Bitbucket repositories centrally and exposes the resulting code graph over MCP. Coding agents, internal chatbots and CI pipelines connect to the same endpoint; requests are authenticated with OIDC and mapped to a role and a squad from LDAP group membership.

self-hosted MCP / JSON-RPC OIDC + LDAP squad isolation MIT

The problem

Code intelligence tooling is built for one developer on one laptop

Where several teams work across the same repositories that breaks three ways: the same repository is reindexed on every machine, one team's graph is unreachable to another, and none of it can be queried from CI or a chatbot because the data lives on somebody's disk.

CENTRAL INDEXING

Index once, everyone reads it

A connector covers one GitHub organisation, GitLab group or Bitbucket workspace. A newly created repository is picked up on the next scan with no configuration change.

THREE INDEPENDENT LAYERS

Authorization is not one gate

Role capabilities and the project allowlist in the gateway, a tool profile in the engine, a separate filesystem root per squad. A mistake in one layer does not open the others.

NO RESTART

Configuration that changes while it runs

Squads, roles, connectors and encrypted tokens live in PostgreSQL. Every change advances a generation counter that both services watch.

ANSWERS FROM THE GRAPH

The model is never asked to guess

ask_codebase runs get_architecture and search_graph first and answers only from what they returned, citing the qualified name of every symbol.

TWO SURFACES, ONE BEHAVIOUR

The terminal and the console agree

repo-mcp-admin and the web console call the same functions, go through the same validation and produce the same audit entry. A test fails if they ever diverge.

AUDIT

Every call, refusals included

One line of JSON per tool call on stdout. Configuration changes are additionally recorded in an audit table in the database.

The interface

Somewhere to look at the graph

The interface is at /ui. It was not written from scratch: the engine project's own interface (React and Three.js, MIT) was adopted and pointed at this platform. Every question it asks about a codebase goes to /mcp with the signed-in user's own token — so anything the browser can do, an MCP client can do, authorized by exactly the same code.

A control the platform would refuse is not hidden — it is disabled with the reason on it. A refusal that arrives is shown in the platform's own words: 'manage_adr' is not available in this session (role: lead, squad: payments). Nothing fails silently.

Use cases

Who reaches for it, and why

Developer · coding agent

“What breaks if I change this?”

Your agent connects without indexing anything locally. The graph is central and current within minutes of the last merge. The answer is not a guess: the graph query runs first.

  • What calls a symbol — search_graph, trace_path
  • What a change affects — detect_changes
  • The relevant source — get_code_snippet

Team lead

Your own service in full, everyone else's as topology

A squad sees its own code in detail and other squads' services only as structure. Cross-service questions get answered without source leaving the squad that owns it.

  • Squad scope from LDAP groups, project allowlist by glob
  • The scout profile: structure, no source
  • A shared org-public layer: topology for everyone

Platform team · DevOps

One command to stand it up, no restart to change it

Four containers is enough with Compose; bring your own identity provider and model proxy and the optional images are never pulled. Configuration lives in the database and reaches the services on its own.

  • make setup writes the profiles from five questions
  • The Helm chart refuses an unpinned image tag in production
  • The terminal and the web console do the same things

CI pipeline

A blast-radius comment on the pull request

A job connecting as a service account can compute the impact set from the graph and have it summarised. No per-repository job to configure.

  • The bundled Keycloak realm ships a service client for CI
  • explain_change_impact runs detect_changes first
  • Reindex by webhook, scheduled scan or CI trigger

Install

Five minutes, four commands

Docker Engine 24+ and Compose v2 is all it needs. It runs on Linux; the engine binary is downloaded statically linked for linux/amd64 and linux/arm64.

Clone and configure

Five questions — database, identity, model backend, compression, provider — written to deploy/.env.

git clone https://github.com/emrezdemir/repo-mcp
cd repo-mcp && make setup

Bring it up

The schema is created, the first administrator is made and its password is printed once.

make up

Define a connector

From the terminal or the web console — both call the same function. check asks the provider what it can actually see.

repo-mcp-admin secret set connector.acme-github.token
repo-mcp-admin connector set acme-github \
  --provider github --squad payments --setting org=acme \
  --token-secret connector.acme-github.token
repo-mcp-admin connector check acme-github
acme-github: ok — 34 of 41 repositories would be indexed

Connect

A browser at http://localhost:8080/ui, an MCP client at POST /mcp.

curl -s http://localhost:8080/mcp \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

For development without Docker, make dev creates a local SQLite database, starts both services with auto-reload, and prints the token to use.
